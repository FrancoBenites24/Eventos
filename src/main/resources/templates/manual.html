Manual de usuario

Documento operativo muy detallado que explica paso a paso como usar la plataforma para descubrir eventos, comprar entradas digitales con QR y administrarlos como organizador. Todo el flujo descrito aqui existe en la aplicacion, basado en los controladores, servicios y plantillas del proyecto.


Referencias tecnicas usadas en este manual: Thymeleaf para vistas, Spring Security para autenticacion, openhtmltopdf para PDF, ZXing para QR y JavaMail para envios de boletas.

1Alcance y publico

El manual describe todo el recorrido dentro de la aplicacion Eventos: aterrizaje, registro, compra de entradas digitales con QR, gestion de billetera y panel para organizadores. Incluye detalles finos sobre validaciones, mensajes de error, tiempos de reserva y archivos generados.

Publico

  • Visitantes que solo navegan y consultan eventos.
  • Usuarios registrados que compran y almacenan tickets.
  • Organizadores que publican y editan eventos.

Que no cubre

  • Detalles de despliegue en servidores.
  • Configuracion de base de datos o Redis.
  • Personalizacion de estilos CSS avanzada.

2Roles y permisos

Rol Acceso principal Detalles operativos
Visitante Landing e indice de eventos publicados. Puede abrir detalle de evento y ver tickets disponibles, pero no agregarlos al carrito.
Usuario registrado Compra de entradas, billetera, perfil. Debe iniciar sesion; el carrito y checkout usan la sesion activa. Puede recibir boletas por correo.
Organizador Panel /organizador, creacion/edicion de eventos. Ve dashboard, crea eventos con imagenes, tarifas y ubicacion, publica o mantiene en borrador.

El control de acceso se maneja con Spring Security. Si el usuario no esta autenticado y accede a rutas protegidas (checkout, billetera, perfil u organizador), se redirige a /login con mensaje de error.

3Requisitos previos

Dispositivo y red

  • Navegador moderno (Chrome, Edge, Firefox, Safari) con JS habilitado.
  • Resolucion recomendada: minimo 1280x720 para panel de organizador; el resto es responsive.
  • Conectividad estable para cargar imagenes y enviar formularios.

Datos de usuario

  • Correo valido; el login usa correo verificado.
  • Contrasena de minimo 8 caracteres, con mayuscula, minuscula, numero y simbolo (segun reglas del DTO).
  • DNI de 8 digitos y telefono de 9 a 15 digitos si se desea guardar metodos moviles.

La aplicacion usa zona horaria America/Lima y moneda PEN. Las fechas mostradas y calculos de IGV dependen de esa configuracion.

4Inicio rapido

  1. Desde la landing, abre "Registrate" o la ruta /auth/registro y completa el formulario.
  2. Confirma el correo desde el mensaje enviado por el servicio de verificacion.
  3. Inicia sesion en /auth/login. Si falla, se muestra "Usuario o contrasena incorrectos".
  4. Explora /eventos, entra a un evento y pulsa "Agregar" en el tipo de entrada deseado.
  5. Abre el carrito (off-canvas) o ve a /checkout para revisar montos e impuestos.
  6. Elige metodo de pago (tarjeta, Yape, Plin o billetera si tienes saldo) y pulsa "Pagar".
  7. Recibe boleta y tickets en pantalla y por correo con el PDF adjunto y QR por ticket.
  8. Consulta tu historial en /perfil y tus movimientos en /billetera.

5Descubrimiento de eventos

Landing e indice

  • Ruta / muestra hero, categorias y CTA para organizadores.
  • Ruta /eventos lista tarjetas agrupadas por categoria. Si no hay eventos, se indica al usuario.
  • Se usa CatalogoEventosView para obtener destacado y agrupacion.

Detalle de evento

  • Ruta /eventos/{id} via EventoController.
  • Muestra titulo, descripcion, imagen principal (o placeholder), ubicacion compuesta y organizador.
  • Lista tipos de ticket con nombre visible, precio y cupo. Si el precio minimo es 0 se marca como evento gratuito.
  • Boton "Agregar" envia un POST a /carrito/agregar con entradaTipoId y cantidad.

Ubicacion

Las direcciones se muestran concatenando direccion, distrito, provincia, departamento y pais. Si falta informacion, se reemplaza por "Ubicacion por definir" para evitar campos vacios.

6Carrito y reserva

  • El carrito usa CarritoSession y permanece en la sesion del usuario.
  • Se agregan items via /carrito/agregar y se obtienen conteo y total en centavos en JSON.
  • Se puede eliminar un item con /carrito/eliminar o limpiar con /carrito/limpiar.
  • El panel lateral (off-canvas) se carga desde /carrito/panel y usa el fragmento _offcanvas-cart.
  • Tiempo de reserva sugerido: 15 minutos (config app.reservation-timeout-minutes).

Si el carrito queda vacio, CheckoutController redirige al listado de eventos y muestra el mensaje "Tu carrito esta vacio".

7Pago y checkout

Resumen

  • Ruta /checkout requiere usuario autenticado. Si no lo esta, redirige a /login.
  • Se construye CheckoutResumenView con subtotal, IGV (18%), total y moneda.
  • Si hay billetera asociada se muestra saldo disponible y metodos guardados.

Formulario de pago

  • Campos prefijados con nombre y correo del usuario autenticado.
  • Metodos disponibles: TARJETA, YAPE, PLIN y BILLETERA (solo si hay saldo o billetera creada).
  • Se pueden usar metodos guardados (alias y ultimos digitos) via MetodoPagoGuardadoService.
  • Las validaciones revisan campos obligatorios y formatos. Errores vuelven al checkout con mensajes de campo.

Procesar pago

  1. Boton "Pagar" dispara POST /checkout/pagar.
  2. Se revalida carrito; si quedo vacio se redirige a eventos.
  3. Para billetera se descuenta saldo y se registra WalletTx de debito.
  4. Se crean Orden y OrdenItem por evento y tipo de ticket, con estado PAGADA.
  5. Se genera referencia de pago amigable (JSON con parte visible y oculta segun metodo).
  6. Se crean boleta y tickets digitales y se vacia el carrito.

Los impuestos se calculan con constante IGV del 18% sobre el subtotal. La moneda se lee de app.currency y se muestra como simbolo S/ por defecto.

8Boleta y tickets digitales

  • Tras el pago, CheckoutController retorna la vista confirmacion con datos de la boleta.
  • TicketPdfGenerator convierte la plantilla tickets/ticket-pdf a PDF con openhtmltopdf.
  • Se genera un QR por ticket con ZXing y se incrusta como imagen base64 en el PDF.
  • El email de confirmacion adjunta Entradas-{codigoBoleta}.pdf y marca enviadoEn en la base de datos.
  • Datos incluidos: resumen de pago, items, totales, fecha de pago y detalle por ticket (evento, titular, codigo, QR).

Cada ticket lleva los UUID de orden y item para validaciones posteriores. El usuario debe presentar el QR en el ingreso del evento.

9Billetera y metodos guardados

Visualizar saldo

  • Ruta /billetera (requiere sesion). Si no hay billetera se crea al vuelo.
  • Se muestran saldo, ultima actividad (WalletTx) y metodos guardados.

Recarga

  1. Elige metodo: YAPE, PLIN o TARJETA (BILLETERA no aplica para recarga).
  2. Ingresa monto positivo; se valida que sea mayor a cero.
  3. Si usas metodo guardado, se precarga telefono o ultimos digitos. Si no, completa telefono, codigo de operacion o datos de tarjeta (numero, expiracion MM/YY y CVV).
  4. Opcional: marca "guardar metodo" con alias para reutilizarlo en compras o nuevas recargas.
  5. Al confirmar, se registra WalletTx tipo CR con referencia segun metodo.

Los metodos guardados viven en MetodoPagoGuardado y se validan por usuario. Si el ID no pertenece al usuario se genera error "no esta disponible".

10Perfil y gamificacion

  • Ruta /perfil muestra datos del usuario, nivel y puntos.
  • Las metricas incluyen ordenes totales, entradas activas, eventos asistidos y puntos de gamificacion.
  • La gamificacion calcula nivel cada 500 puntos (puntos = centavos pagados / 100).
  • Se listan ultimas 5 ordenes, proximos eventos o historial, y transacciones de billetera.

Si el usuario no esta autenticado, la ruta responde 401. Esto protege la informacion sensible del perfil.

11Panel de organizador

Dashboard

  • Ruta /organizador/dashboard. Muestra tarjetas con eventos publicados, borradores, entradas vendidas e ingresos.
  • Incluye grafico de ventas por mes y proximos eventos con progreso de ventas.

Listado de eventos

  • Ruta /organizador/eventos con filtros por busqueda, estado (BORRADOR, PUBLICADO, CANCELADO) y categoria.
  • Cada tarjeta muestra progreso de ventas, capacidad total y enlaces a ver, editar o eliminar.

Crear o editar evento

  1. Ruta /organizador/eventos/nuevo o /organizador/eventos/{id}/editar.
  2. Completa: titulo, categoria, descripcion, imagenes (hasta 5), fechas inicio/fin, direccion y mapa interactivo (Leaflet con OpenStreetMap).
  3. Define tipos de entrada: tipo de catalogo, nombre visible, precio (permite 0 para gratis) y cupo.
  4. Activa la casilla "Publicar" para que el evento aparezca en el catalogo al guardar.
  5. Botones: "Guardar/Actualizar evento" y "Cancelar" para volver al listado.

Imagenes y mapa

El mapa permite arrastrar el marcador o hacer clic para actualizar latitud y longitud, con geocodificacion inversa que rellena distrito, provincia y pais. Las imagenes se almacenan y se exponen via /media/eventos/{imagenId}.

12Correos y notificaciones

  • Verificacion de correo: al registrarse se envia codigo y la ruta /auth/confirmar lo valida.
  • Recuperacion de contrasena: formulario en /auth/recuperar genera token; /auth/restablecer valida y cambia la contrasena.
  • Confirmacion de compra: email con asunto configurable (app.mail.ticket-subject) y cuerpo en HTML, adjunta PDF de tickets.
  • Remitente configurado con spring.mail.username y nombre app.mail.from-name.

Si el PDF no puede generarse o el envio falla, se registra en logs pero la compra se mantiene; el usuario puede descargar de nuevo desde su correo cuando se reprocese.

13Seguridad y buenas practicas

  • Contrasenas: minimo 8 caracteres con minuscula, mayuscula, numero y simbolo.
  • Sesiones: rutas protegidas validan Authentication; sin sesion responden 401 o redirigen a login.
  • CSRF: los formularios Thymeleaf incluyen token _csrf cuando esta habilitado.
  • Datos sensibles: DNI y telefono se validan con patrones de numero; no se exponen en listados publicos.
  • Monitoreo: logs de seguridad se configuran con nivel DEBUG para org.springframework.security.

14Resolucion de problemas

Errores comunes al pagar

  • "Tu carrito esta vacio": otro usuario consumio el cupo o limpiaste sesion. Vuelve a agregar entradas.
  • "Metodo de pago guardado no esta disponible": el ID no pertenece al usuario o el tipo no coincide.
  • "Debes ingresar el codigo de operacion": en Yape/Plin falta referencia.
  • "Tarjeta no valida": revisa formato MM/YY y CVV de 3 o 4 digitos.

Acceso y autenticacion

  • No recibiste correo de verificacion: revisa spam y usa /auth/verificacion-pendiente para reenviar.
  • Olvidaste contrasena: usa /auth/recuperar, recibe token y restablece en /auth/restablecer.
  • Sesion caduca al pagar: inicia sesion de nuevo; el carrito se mantiene en la sesion mientras no se cierre.

Panel de organizador

  • Mapa no carga: verifica conexion a tile.openstreetmap.org y que el navegador permita JS.
  • Imagen rechazada: solo se aceptan JPG, PNG, GIF o WEBP y maximo 5 archivos.
  • No se muestra en catalogo: asegurate de marcar "Publicar" y que el estado no sea BORRADOR.

15Anexos rapidos

Rutas clave

  • Landing: /
  • Eventos: /eventos y /eventos/{id}
  • Carrito: /carrito/panel
  • Checkout: /checkout y /checkout/pagar
  • Billetera: /billetera
  • Perfil: /perfil
  • Organizador: /organizador/**

Generacion de documentos

  • Boletas y tickets: plantilla tickets/ticket-pdf + TicketPdfGenerator.
  • Manual PDF: plantilla manual.html + ManualPdfService (este documento).
  • Correos: ConfirmacionCompraServiceImpl usa JavaMail y adjunta PDF.
